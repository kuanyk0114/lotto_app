# 01 開發需求清單 (lotto_app)

## 📋 1. 專案概述與目標

* **專案名稱**：中文「好運自己選」/ 英文 `lotto_app`
* **專案定位**：專業級台灣彩券（台彩）自選號碼歷史數據分析與統計工具。不同於坊間僅提供簡單對獎或隨機選號的 App，本程式主打「自由選號組合分析」，讓使用者根據個人偏好選定任意球數與號碼後，快速比對歷史開獎資料庫，分析過往中獎規律與期別。
* **目標平台**：Windows 桌面版 (已完成) / Android App (已完成) / iOS App (規劃中)。

---

## 🎯 2. 核心功能需求 (Functional Requirements)

### 2.1 五大彩種選號系統
使用者可在各彩種專屬介面中進行自選號組合：
1. **威力彩 (Power Lotto)**：
   - 第一區 (01~38)：最多可選擇 6 個號碼（不需選滿）。
   - 第二區 (01~08)：最多可選擇 1 個號碼。
2. **大樂透 (Big Lotto)**：
   - 選號區 (01~49)：最多可選擇 6 個號碼（不需選滿）。
3. **今彩539 (Lotto 539)**：
   - 選號區 (01~39)：最多可選擇 5 個號碼（不需選滿）。
4. **三星彩 (3-Star Lotto)**：
   - 位置選號：分為「佰位」、「拾位」、「個位」，每位數可選擇 0~9 的數字（不需選滿三位數）。
5. **四星彩 (4-Star Lotto)**：
   - 位置選號：分為「仟位」、「佰位」、「拾位」、「個位」，每位數可選擇 0~9 的數字（不需選滿四位數）。

### 2.2 五大分析與管理功能
針對上述五大彩種，皆必須提供以下五項核心功能：

#### (1) 選號查詢 (Query Numbers)
- **說明**：使用者選取任意數量的號碼（自選號）後，系統比對歷史開獎資料庫 `lotto_history.db`。
- **輸出**：列出所有包含自選號的中獎期別、開獎日期、開獎號碼（自選號需以高亮/特殊顏色顯示）及中獎獎別。
- **統計**：顯示中獎總筆數，並依據獎別統計中獎次數。
- **排序**：支援依開獎日期進行升序或降序排列。

#### (2) 查重複獎號 (Check Duplicate Numbers)
- **說明**：分析歷史開獎紀錄中，曾開出過完全相同多碼組合的統計資訊。
- **分析組合**：
  - 威力彩 / 大樂透：查詢歷史開出重複 6 碼的組合。
  - 今彩539：查詢歷史開出重複 5 碼的組合。
  - 三星彩 / 四星彩：查詢歷史開出完全相同 3 碼 / 4 碼的組合。
- **互動**：顯示重複獎號及其歷史開出次數，點選特定重複組合可進一步查看詳細的中獎期別與日期。

#### (3) 自選號中獎詳情 (Check Details)
- **限制**：使用者必須選滿該彩種規定之球數（威力彩第一區需選滿6碼，第二區可選可不選；大樂透6碼；今彩539 5碼；三星彩3碼；四星彩4碼）。
- **說明**：計算該組完整號碼若在歷史各期投注，累計可獲得的各獎項中獎筆數與詳細期別對照。

#### (4) 儲存與提取自選號 (Save & Load Custom Numbers)
- **儲存**：可將當前選號盤上的號碼組合儲存至本地用戶資料庫 `custom.db` 中。（威力彩支援僅選滿第一區即儲存）。
- **提取**：彈出自選號清單，點選特定組合可直接帶回主選號盤；支援長按（Long Press）防誤觸刪除功能。

#### (5) 近期獎號查詢 (Recent Prize Query)
- **說明**：提供獨立專屬介面，分頁展示各彩種最新及歷史前幾期的開獎號碼、開獎日期、期別與獎金分配資訊。

## 🛠️ 3. 非功能性需求 (Non-Functional Requirements)

### 3.1 系統效能與大數據優化
- **分頁載入機制 (`BasePaginationMixin`)**：針對動態查詢結果進行分頁展示（每頁 30 筆），避免一次性載入數千筆歷史資料導致 UI 卡頓或記憶體溢出（OOM）。
- **滾動位置精確恢復**：當使用者載入更多資料或切換頁面時，自動計算並恢復絕對滾動高度，維持流暢的操作體驗。

### 3.2 UI/UX 與跨平台視覺
- **統一視覺風格**：採用高品質黃金/暗色系配色，搭配高辨識度的彩色彩球（`ResultBall`）與立體按鈕。
- **中文字體相容**：全面整合 `NotoSansTC-Regular.ttf`，解決 Windows/Android 平台上的中文缺字與亂碼問題。
- **高 DPI 螢幕與觸控優化**：
  - 適應各類 Android 手機解析度，防止介面縮放或偏移。
  - 實作 100ms 觸控冷卻防重送機制（Debounce），防範 Android 多點觸控或快速點擊導致的重複觸發事件。

### 3.3 資料同步與營運需求
- **雲端增量同步 (Supabase)**：App 啟動時自動透過 REST API 連線 Supabase 伺服器，比對 `data_list` 並增量下載最新開獎 CSV 檔案，自動更新本地 `lotto_history.db`。
- **版本比對與強迫/彈性更新**：比對 Supabase `app_ver` 資料表，若有新版本則自動彈出提示引導使用者更新。
- **商業化廣告與免責聲明**：
  - 整合 Google AdMob 橫幅廣告 (AdBanner)。
  - 提供動態載入 Markdown (`服務條款與法律免責聲明隱私權政策.md`) 的隱私權政策與法律免責聲明彈窗。
