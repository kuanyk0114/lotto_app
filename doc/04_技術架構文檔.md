# 04 技術架構文檔 (lotto_app)

## 🏗️ 1. 系統架構總覽 (System Architecture Overview)

`lotto_app` 採用基於 **Python 3.11+** 與 **Kivy 2.3.1** 框架的分層模組化架構（Layered Architecture），實現跨平台（Windows / Android）的高效運作。整體系統包含前端展示層、業務邏輯層、本地持久化層與雲端同步層。

```
+-------------------------------------------------------------------+
|                     UI 展示層 (Kivy View Layer)                   |
|  main.py / kv/*.kv (LotteryTypeScreen, PowerLottoScreen, etc.)    |
+-------------------------------------------------------------------+
                                  │ (Event Bindings & Properties)
                                  ▼
+-------------------------------------------------------------------+
|                   業務邏輯層 (Business Logic Layer)                |
| modules/ (common.py, powerlotto.py, biglotto.py, lotto539.py...)  |
| - BasePaginationMixin (分頁與數據控制)                            |
| - 歷史彩球比對與統計演算法                                        |
+-------------------------------------------------------------------+
                 │                                    │
                 ▼                                    ▼
+---------------------------------+  +------------------------------+
| 本地持久化層 (SQLite Data Layer)|  |  雲端同步層 (Supabase Cloud) |
| data/lotto_history.db (歷史獎號)|  |  modules/sync.py             |
| data/custom.db (用戶自選號)     |  |  - REST API / Storage Bucket |
+---------------------------------+  +------------------------------+
```

## 📁 2. 模組職責分工與檔案目錄細節

| 檔案/模組名稱 | 職責劃分與核心功能 |
| :--- | :--- |
| `main.py` | 應用程式入口。初始化 Kivy Config、載入中文字型、註冊 ScreenManager 並啟動 App。 |
| `modules/common.py` | 全局共用基礎組件。包含 `LotteryTypeScreen`（主畫面）、`BasePaginationMixin`（分頁基類）、`ExitConfirmPopup`（退出彈窗）與 `show_privacy_policy`（Markdown 隱私權政策載入器）。 |
| `modules/powerlotto.py` | 威力彩專屬業務邏輯。處理雙區選號比對、歷史頭獎6碼重複統計、自選號中獎詳情計算。 |
| `modules/biglotto.py` | 大樂透業務邏輯。49選6號碼矩陣運算與歷史中獎矩陣比對。 |
| `modules/lotto539.py` | 今彩539業務邏輯。39選5號碼矩陣運算與重複5碼統計。 |
| `modules/lotto3star.py` / `lotto4star.py` | 三星彩與四星彩業務邏輯。位置陣列號碼搜尋與重複3碼/4碼直選比對。 |
| `modules/sync.py` | 雲端資料同步組件。透過 REST API 連線 Supabase 檢查最新 CSV，下載解譯並寫入本地 SQLite。 |

## 🗄️ 3. 資料庫設計 Schema (Database Design)

### 3.1 本地 SQLite 資料庫 (`data/lotto_history.db`)
儲存台灣彩券歷年完整開獎號碼與版本資訊：

1. **`power_lotto` (威力彩歷史獎號表)**
   - `id` (INTEGER, PK), `game_name` (TEXT), `issue` (TEXT, 期別), `date` (TEXT, YYYY-MM-DD), `total_sales` (INTEGER), `tickets_sold` (INTEGER), `total_prize` (INTEGER), `num1`~`num6` (INTEGER, 第一區獎號), `special_num` (INTEGER, 第二區號碼)。
2. **`big_lotto` (大樂透歷史獎號表)**
   - 欄位結構與威力彩類似，`num1`~`num6` 為開獎號碼，`special_num` 為特別號。
3. **`lotto_539` (今彩539歷史獎號表)**
   - 包含 `num1`~`num5` 獎號。
4. **`lotto_3star` / `lotto_4star` (三星彩 / 四星彩歷史獎號表)**
   - 三星彩包含 `num1`~`num3`（佰/拾/個位）；四星彩包含 `num1`~`num4`（仟/佰/拾/個位）。
5. **`updated_data` (增量更新紀錄表)**
   - `id` (TEXT, 增量檔案版本號), `updated_at` (TEXT, 更新時間)。

### 3.2 用戶資料庫 (`data/custom.db`)
儲存使用者個人自選號碼組合：
* **`custom_numbers` 表**：
  - `id` (INTEGER, PK AUTOINCREMENT)
  - `lottery_type` (TEXT: `power`, `big`, `539`, `3star`, `4star`)
  - `num1`~`num6`, `special_num` (INTEGER)
  - `created_time` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

### 3.3 雲端 Supabase PostgreSQL & Storage
- **`data_list` 表**：記錄可供下載之 CSV 更新檔清單與 SHA-256 校驗碼。
- **`lotto_new_number` Bucket**：儲存各期增量開獎 CSV 檔案。

## ⚡ 4. 關鍵技術機制與效能優化 (Critical Mechanisms)

### 4.1 動態分頁與記憶體優化 (`BasePaginationMixin`)
為防範一次性查詢數萬筆歷史紀錄導致 UI 線程阻塞，系統實作動態分頁機制：
- 每頁僅渲染 30 筆 `BoxLayout` 條目。
- 當使用者滾動至列表底部時，觸發 `is_loading_more` 狀態加載下一頁。
- 結合精確的絕對滾動距離計算 (`_restore_scroll_position_absolute`)，確保加載新頁面時視圖不跳動。

### 4.2 行動端防重複觸發冷卻機制 (Touch Debounce)
Android 裝置多點觸控或快速連擊易引發雙重觸控事件（Double Touch），導致按鈕狀態互相抵消。
- 系統於核心觸控組件中實作 **100ms 冷卻計時器**，忽略短時間內的重複 click/touch 事件，大幅提升 Android 實機操作穩定度。

### 4.3 輕量化 Supabase REST API 通訊
因應 Android Buildozer 打包 Python `supabase` SDK 時編譯 Rust 依賴過於龐大且易失敗的問題，本專案直接封裝原生 `requests` 庫，透過 HTTPS REST API 直接與 Supabase 端點通訊，達到極輕量、零額外原生依賴的目標。
